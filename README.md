## The idea

Instead of isolated exercises, I built a lab framed as a **junior system-administrator role at a fictional company, "Caspian Tech LLC"**, and worked through it in phases (P0 → P10) — provisioning, hardening, services, storage, users, automation — **proving every step with captured evidence** before marking it done.

## Highlights

- 🧩 **Phased delivery (P0–P10)** — each phase has objectives, execution, and a verification gate. No step is "done" without proof.
- ✅ **48/48 validation checks passing** — automated verification re-run to confirm the environment holds together.
- 🖥️ **Two-tier setup** — a hardened server (`rhel-srv01`) and a client (`rhel-cli01`) with **key-only SSH**.
- 🔐 Security-minded defaults: SSH hardening, firewalld, least-privilege users, SELinux left enforcing.
- 📄 **Professional report** — a full written report (EN + a ~120-page Azerbaijani PDF) documenting the whole engagement, generated from a build script.

## Skills demonstrated

`RHEL 9` · `system hardening` · `SSH key auth` · `firewalld` · `storage & LVM` · `systemd services` · `evidence-based documentation` · `technical reporting`

## Why it matters for me

This is the closest thing I have to a "first job" on paper: scoped work, executed carefully, verified honestly, and written up so someone else could audit it. That discipline — *document it so the fix (or the fact) is undeniable* — is exactly what I want to carry into security work.
